# 戦車の3Dモデル化：描画負荷の見積もりと頂点数の決定

## 結論

| 項目 | 決定値 |
|---|---|
| 描画ライブラリ | three.js 0.187（WebGL2、必要部分のみ tree-shake して同梱） |
| 戦車1台のモデル | **1,232 三角形 / 3,696 頂点**（detail = 2、1 メッシュ・マテリアル3種） |
| 想定同時表示数 | 30 台（プレイヤー + NPC 最大5） |
| 1フレームの総量 | 約 74,000 三角形（影パスを含む）、描画コール 181 |
| 計測結果（実機 GPU） | 2.8 ms/フレーム（60fps の予算 16.7 ms の約 17%） |

## 見積もりの考え方

### 1. 画面上の大きさが上限を決める
戦車の当たり判定は半径 14px、モデルは 25 × 22 px で描画される（盤面 800 × 600 を 1:1 で表示）。
1 台あたり約 550 ピクセルしかないため、数千三角形のモデルを用意しても見た目の差は出ず、
三角形が 1 ピクセル未満になるとかえってラスタライズの効率が落ちる。
→ 見た目の上限は 1 台あたり千数百三角形程度。

### 2. 描画コストの内訳
- **頂点処理**：三角形数に比例。戦車は 1 ジオメトリに結合しており、台数が増えても頂点データは共有。
- **ドローコール**：材質ごとに分割（チーム色 / 履帯 / 金属）。1 台 = 3 コール、影パスで 2 倍。
- **フラグメント処理**：盤面 800 × 600 固定なので台数・モデル詳細度に依存せず一定。

### 3. 実測（`/bench`）
`client3d/bench.js` は本番と同じレンダラー（影・トーンマッピング・MSAA込み）で、30 台を動かしながら
`readPixels` で GPU 完了まで待った ms/フレームを測る。
環境：AMD Radeon Pro 580X（Metal / ANGLE）、DPR 1、30 台、90 フレーム平均。

| detail | 三角形/台 | 頂点/台 | 総三角形/フレーム | ms/フレーム |
|---|---|---|---|---|
| 1 | 632 | 1,896 | 37,922 | 2.71 |
| **2（採用）** | **1,232** | **3,696** | **73,922** | **2.78** |
| 4 | 2,432 | 7,296 | 145,922 | 2.96 |
| 8 | 4,832 | 14,496 | 289,922 | 3.03 |
| 16 | 9,632 | 28,896 | 577,922 | 3.45 |
| 1（影なし） | 632 | 1,896 | 18,962 | 2.09 |

100 台でも detail 2 が 3.9 ms、detail 16（約 193 万三角形）で 6.5 ms。

読み取れること：
- 三角形あたりの増分は約 1.5 ns（0.0015 ms / 千三角形）。**頂点数はこの規模では支配項ではない**。
  2.1〜2.7 ms の大半は影マップ・MSAA・同期などの固定費。
- 影パスが約 0.6 ms（三角形・コールが 2 倍になる分）。

### 4. 低性能端末への余裕
計測機はデスクトップ GPU。統合 GPU・モバイルが 10〜50 倍遅いと見ても、
頂点処理の追加分（74k 三角形 × 1.5 ns ≒ 0.11 ms）は 50 倍でも約 5.5 ms で 16.7 ms に収まる。
固定費（影・MSAA）が重い端末向けには `createRenderer3D(canvas, { shadows: false })` で
約 0.6 ms 削減できる。

### 5. detail = 2 を選んだ理由
- 見た目：detail 2 で砲塔・転輪の円が 16〜20 角形になり、25px 程度の表示では角が判別できない。4 以上は画面上の差が出ない（理由は 1 を参照）。
- 余裕：30 台でも 7.4 万三角形。上記の通り低性能端末でも予算内。
- 設定：`src/client.ts` の `TANK_3D_DETAIL` で変更可能。

## モデルの構成（`client3d/tank-model.js`）
手続き生成（外部モデルファイル無し）。前方 +X、上 +Y、寸法は当たり判定（長さ 25.2 / 幅 22.4）に一致。

- 履帯 × 2（角丸の側面形状を押し出し）＋転輪 5 個 × 2（起動輪・誘導輪は大きめ）
- 車体：前面傾斜装甲つきの箱。履帯の上にかぶさる幅にして、真上からチーム色が主に見えるようにしてある
- 砲塔（10 角柱を楕円に伸ばしたもの）＋防盾、砲身、マズルブレーキ、ハッチ、アンテナ
- マテリアル：0 = チーム色（車体・砲塔）、1 = 履帯・ハッチ、2 = 金属（転輪・砲身・アンテナ）

## 描画ライブラリの組み込みと確認

- `npm i -D three esbuild`。`client3d/` のソースを esbuild でバンドルし `public/js/` に出力
  （`npm run build:client3d`。`wrangler.jsonc` の `build.command` により `wrangler dev` / `deploy` の前に自動実行）。
- 配信は Workers Static Assets（`assets.directory = ./public`）。`/` と `/ws` は従来どおり Worker が処理。
- バンドルサイズ：`renderer3d.js` 559 KB（gzip 約 145 KB）。ゲーム起動時に動的 import。
- カメラ：盤面中央真上の透視投影。地面（y = 0）が盤面 800 × 600 px にちょうど対応するようにしてあり、
  2D キャンバス（シールド・ゲージ・名前・弾・エフェクト）は 3D キャンバスの上に重ねて位置が一致する。
- 色：自機 = 青、他プレイヤー = 赤、NPC = 灰（従来の色割り当てのまま）。撃破された戦車は焦げた暗色。被弾フラッシュは発光で表現。
- フォールバック：three.js の読み込み失敗や WebGL 非対応の場合は従来の 2D 三角形描画に自動で戻る（確認済み）。
- 確認用ページ：`/bench`（負荷計測）、`/viewer`（モデルのクローズアップ。`?detail=` `?angle=` `?dist=` `?elev=`）。
